טבלת ROLES

CREATE TABLE IF NOT EXISTS Roles (
    Role_id SERIAL PRIMARY KEY,      -- מזהה ייחודי לכל תפקיד
    Role_name VARCHAR (50) NOT NULL   -- שם התפקיד, לדוג' "User", "Admin", GUEST
);

### 1. **הישויות והשדות בבסיס הנתונים (DB)**

#### א. **משתמש (Users)**
נוסיף שדה **`role`** כדי לנהל את התפקידים השונים של המשתמשים. התפקידים יכולים להיות:

- **אורח (Guest)** – משתמש שלא נרשם, יכול רק לצפות במוצרים.
- **משתמש (User)** – משתמש רשום שמבצע פעולות כמו הוספת מוצרים, בקשות להחלפה וכו'.
- **מנהל (Admin)** – מנהל המערכת שיכול לגשת לכל הפונקציות באתר (למשל ניהול משתמשים, מחיקת מוצרים לא ראויים, סינון תוכן וכו').
#### עדכון מודל `Users`:
#### **משתמש (Users)**

| שדה                    | סוג נתון | תיאור                                                 |
| ---------------------- | -------- | ----------------------------------------------------- |
| `user_id`              | INT (PK) | מזהה ייחודי למשתמש (מפתח ראשי)                        |
| `name`                 | VARCHAR  | שם המשתמש                                             |
| `email`                | VARCHAR  | כתובת דוא"ל (יכולה להיות גם מייל פייסבוק או גוגל)     |
| `password_hash`        | VARCHAR  | סיסמא גיבוב (לא הסיסמא עצמה)                          |
| `profile_picture`      | VARCHAR  | URL לתמונת פרופיל                                     |
| `location`             | VARCHAR  | אזור/מקום מגוריו של המשתמש (כגון תל אביב, חיפה)       |
| `auth_provider`        | VARCHAR  | מקור ההתחברות (Facebook, Gmail או מקומי)              |
| `role_id`              | INT (FK) | מזהה התפקיד, מצביע לטבלת `Roles` (Guest, User, Admin) |
| `notification_enabled` | BOOLEAN  | האם המשתמש מעוניין לקבל התראות                        |
| `is_banned`            | BOOLEAN  | האם המשתמש חסום לאחר דיווחים                          |
| `created_at`           | DATETIME | תאריך יצירה של המשתמש                                 |
| `updated_at`           | DATETIME | תאריך עדכון אחרון של פרטי המשתמש                      |
#### הסבר:
- **`role`**: שדה זה יהיה **ENUM** ויכלול ערכים כמו "Guest", "User", "Admin". כך נוכל לשלוט על הגישה לפונקציות השונות באתר.

#### ב.  **מוצר (Product)** 

| שדה           | סוג נתון | תיאור                                                                 |
| ------------- | -------- | --------------------------------------------------------------------- |
| `product_id`  | INT (PK) | מזהה ייחודי למוצר                                                     |

| `image_url`   | VARCHAR  | URL לתמונת המוצר                                                      |
| `created_at`  | DATETIME | תאריך העלאת המוצר                                                     |
| `updated_at`  | DATETIME | תאריך עדכון אחרון של המוצר                                            |

#### ג. **פאזל (Puzzle)** (מתחבר למוצר)

הפאזל הוא מוצר מסוג **Puzzle** אך יש לו קטגוריית משנה ספציפית שיכולה לכלול סוגים כמו:

- טבע (פאזלים עם תמונות של טבע, נופים)
- ציורים (פאזלים עם ציורים אמנותיים)
- ילדים (פאזלים עם תמונות קלות לילדים)
- תלת-ממד (פאזלים שהם גם תלת-ממדיים)

|שדה|סוג נתון|תיאור|
|---|---|---|
|`product_id`|INT (PK, FK)|מזהה המוצר (קשר למוצר)|
|`manufacturer`|VARCHAR|יצרן הפאזל|
|`pieces_count`|INT|מספר החלקים בפאזל|
|`image_url`|VARCHAR|URL לתמונה שמייצגת את הפאזל|
|`subcategory`|VARCHAR|קטגוריית משנה (טבע, ציורים, ילדים, 3D)|

---

#### ד. **ספר (Book)** (מתחבר למוצר)
הספר הוא מוצר מסוג **Book** ויש לו קטגוריית משנה שיכולה להיות:

- רומן
- מתח
- פנטזיה
- מדע בדיוני
- ילדים
- עיון
- ביוגרפיה
- ספרי לימוד
- ספרי עיון

|שדה|סוג נתון|תיאור|
|---|---|---|
|`product_id`|INT (PK, FK)|מזהה המוצר (קשר למוצר)|
|`author`|VARCHAR|שם הסופר|
|`publish_year`|INT|שנת הוצאה|
|`publisher`|VARCHAR|הוצאת ספרים|
|`page_count`|INT|מספר עמודים|
|`image_url`|VARCHAR|URL לתמונה של כריכת הספר|
|`subcategory`|VARCHAR|קטגוריית משנה של הספר (מתח, פנטזיה, רומן, מדע בדיוני וכו')|

---

#### ה. **משחק קופסה (Board Game)** (מתחבר למוצר)

המשחק קופסה הוא מוצר מסוג **Board Game** ויש לו קטגוריית משנה שיכולה לכלול: 

| שדה           | סוג נתון     | תיאור                                                  |
| ------------- | ------------ | ------------------------------------------------------ |
| `product_id`  | INT (PK, FK) | מזהה המוצר (קשר למוצר)                                 |
| `game_name`   | VARCHAR      | שם המשחק                                               |
| `min_players` | INT          | מינימום שחקנים                                         |
| `max_players` | INT          | מקסימום שחקנים                                         |
| `duration`    | INT          | זמן משחק ממוצע                                         |
| `image_url`   | VARCHAR      | URL לתמונה שמייצגת את משחק הקופסה                      |
| `subcategory` | VARCHAR      | קטגוריית משנה (אסטרטגיה, משחקי ילדים, משחקי חברה וכו') |

---

#### ו. **בקשה להחלפה (Exchange_Request)**
- אסטרטגיה
- משחקי ילדים
- משחקי חברה
- משחקי חידות
- משחקים לשניים
- משחקי קבוצה

| שדה                   | סוג נתון | תיאור                                 |
| --------------------- | -------- | ------------------------------------- |
| `request_id`          | INT (PK) | מזהה ייחודי לבקשה (מפתח ראשי)         |
| `user_id`             | INT (FK) | מזהה המשתמש שביקש את ההחלפה           |
| `product_id`          | INT (FK) | מזהה המוצר המוצע להחלפה               |
| `exchange_product_id` | INT (FK) | מזהה המוצר המבוקש להחלפה              |
| `status`              | ENUM     | סטטוס הבקשה (ממתין, מאושר, נדחה)      |
| `created_at`          | DATETIME | תאריך יצירת הבקשה                     |
| `updated_at`          | DATETIME | תאריך עדכון הבקשה                     |
| `chat_id`             | INT (FK) | מזהה הצ'אט של המשתמשים בקשר להחלפה זו |
#### הסבר:

- שדה **`status`**: אם הבקשה עדיין "ממתינה" לאישור, "מאושר" או "נדחה".
- שדה **`user_id`** ו-**`product_id`** הם **Foreign Keys** שיקשרו את הבקשה למשתמש ולמוצר.

|שדה|סוג נתון|תיאור|

|שדה|סוג נתון|תיאור|
|---|---|---|
